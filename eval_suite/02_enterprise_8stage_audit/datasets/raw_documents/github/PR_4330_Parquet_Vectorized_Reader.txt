GitHub Pull Request #4330: Fix buffer reallocation in Parquet vectorized reader for high-precision decimals
Repo: internal-engine / spark-fork

Reviewers: Marcus Vance (@marcusv)
Status: Merged (Commit: b14d89a)
Related Issues: Resolves SPARK-43288

Overview:
Fixes off-heap memory corruption in `VectorizedColumnReader.java` when reading `Decimal(38, 18)` columns from Parquet files.

Diff:
```java
// sql/core/src/main/java/org/apache/spark/sql/execution/datasources/parquet/VectorizedColumnReader.java
- int requiredBytes = numValues * 8;
+ int typeWidth = (precision > 18) ? 16 : 8;
+ int requiredBytes = numValues * typeWidth;
+ if (offHeapBuffer.capacity() < requiredBytes) {
+   offHeapBuffer.reallocate(requiredBytes * 2);
+ }
```

Validation:
Added unit test `VectorizedDecimalReadSuite.scala` reading 1,000,000 rows of random 38-digit numbers. Zero SIGSEGV and clean memory valgrind check.

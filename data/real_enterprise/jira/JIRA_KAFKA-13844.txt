Title: Zombie transactional producer fencing failure during network partition

Description:
During an AWS transit gateway network partition between `us-east-1a` and `us-east-1b`, a transactional producer for settlement transactions was partitioned away and re-instantiated on a secondary instance with the same `transactional.id`.

The original producer resumed sending data after the network healed and was not fenced because `producer.epoch` was not incremented correctly during concurrent transaction abort.

Resolution:
Resolved in GitHub PR #1385. Enforced atomic epoch increment and verification inside `TransactionCoordinator.appendTransactionMetadata` prior to accepting CommitTransaction requests. Added deterministic integration test `TransactionFencingIntegrationTest.scala`.

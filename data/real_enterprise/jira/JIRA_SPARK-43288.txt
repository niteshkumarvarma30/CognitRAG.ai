Title: Parquet vectorized column reader buffer overflow on Decimal(38, 18) columns

Description:
Queries reading Delta Lake tables with high precision decimal currency fields (`Decimal(38, 18)`) encounter `java.lang.IndexOutOfBoundsException` or JVM SIGSEGV crashes when vectorized reader (`spark.sql.parquet.enableVectorizedReader = true`) encounters dictionary-encoded pages exceeding 4MB.

Root Cause:
In `VectorizedColumnReader.java`, the allocated off-heap buffer size was calculated assuming fixed 8-byte integer storage rather than 16-byte decimal representations when decoding byte array dictionaries.

Resolution:
Resolved in GitHub PR #4330. Clamped buffer reallocation calculation to allocate 16 bytes for precision > 18 and added bounds checking before off-heap memory copy. Backported to maintenance release 3.5.2.
